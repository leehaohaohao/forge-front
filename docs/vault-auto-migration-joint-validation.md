## 结果

| 场景 | 实测结果 |
| --- | --- |
| 首次创建 / 已有保险库解锁 | 创建、下载及验证恢复材料后自动开始；已有保险库解锁即继续，无迁移二次认证或旧向导 |
| 多页历史数据 | 单账号 53 条跨页迁移；包括软删除，不受列表分页/筛选影响；最终状态完成后进度收起 |
| 字节完整性 | 独立 Node WebCrypto 使用实际下载的恢复材料解开保险库，再解开每条迁移密文，逐字节等于迁移前值；查看和复制保留 BOM、纯空白、NUL 和组合字符 |
| 新用户 | 无迁移步骤；实际新增、查看、复制成功；加密备份导出后在独立恢复页面上传备份、校验和与恢复材料，恢复验证通过 |
| 锁定与丢失响应 | 真实 source 响应暂停期间锁定不提交；重新解锁自动继续；真实 commit 已成功但响应丢失后核对状态并完成 |
| 迁移中刷新 | 已提交事务的响应尚未返回时刷新，页面恢复锁定，重新解锁按持久化状态续传；已有日常密文整行未改动 |
| 断网 | 保留未完成项；恢复网络并重试完成 |
| 双上下文并发 | 同账号两个浏览器上下文并发，观察到 12 次实际 409 冲突，最终完成，无覆盖或重复 secret ID |
| 单行失败 | 空值、超长值保留原值与 revision，其余记录继续；不误报完成；错误状态仍可查看、复制已迁移项并实际新增密钥 |
| 篡改交付包 | 修改真实 JWE tag 后拒绝提交该条，其余继续；重试真实包后完成 |
| 全部软删除 | 仅软删除的 3 条也迁移，日常列表不重新出现 |
| 鉴权及写入边界 | 跨用户 source/commit 拒绝；无效和签名有效但已过期的 JWT 拒绝；原提交重放得到 already_committed；普通接口新增旧明文被拒绝 |
| 真实限流 | 耗尽实际 status 限流桶触发 429；遵守 Retry-After 自动恢复，等待时无绕过退避的重试按钮，新增仍可用 |
| 兼容关闭 | 重启服务关闭兼容开关，无自动 source/commit，直接 source 返回 40920；正常新增、查看、复制成功 |
| 日志及旧接口 | 合成秘密、密码、恢复密钥未出现在检查日志；正常页面没有旧迁移链路请求 |

最终 84 条历史记录中 82 条完成，2 条预设坏数据保持原样；另新增 3 条正常密钥，共 87 条。
数据库最终 85 条客户端密文、85 个唯一 secret ID；已迁移记录旧值清空、revision 恰好增加 1。
