# 保险库用户流程补齐：前1交付

日期：2026-10-26。基于前端 main 79749cc，依赖后端 F1 契约（后1 f4c51ad）。对应后端 docs/vault-user-flow-and-migration-plan.md 第5节。

## 已实现

- 顶部编号步骤条：创建、保存并验证恢复材料、按需出现的迁移、开始使用。完成节点保留数字；按真实状态高亮，不允许点编号推进。无迁移历史省略迁移节点，已切换历史保留节点。
- 本地草稿使初始流程停在恢复确认；自动锁定仍保留该步，明确放弃才回到创建。已有保险库的正常锁定、修改密码、凭据恢复不会重置首次准备进度。
- 每步中性圆形感叹号提供用途、顺序及完成条件；支持悬浮、键盘聚焦、点击保持、关闭按钮与 Escape。帮助不含秘密，不发请求、不改变保险库状态。
- GET /vault/migration-status 严格解析：保留精确字符串ID，使用全量活跃/软删除数量、批次及审计状态。verified、审计失败不能显示完成；switched 且 audit complete 才完成切换。
- 锁定时“新增密钥”可点击，定位独立密码输入；解锁后打开空白表单，不自动提交。取消、锁定及离页清除意图，解锁前不接收业务明文。混合新旧数据不限制正常新增，冻结及上限按能力给出短说明。
- 历史“待迁移”入口定位迁移区域；状态和数量保持简短，职责、文件交付方式放进帮助。移除重复常驻说明，将元数据明文提醒放到实际编辑表单。
- 失败保留旧视图但不推进、不开放准备操作；可重试。没有后台轮询，手动刷新、重新可见及保险库保存后重新读取；隐藏/离页取消请求，晚到响应无效。失败重试至少等待10秒，429遵守 Retry-After。
- 窄屏纵向步骤、收起侧栏、可收缩搜索、表格独立横向滚动，避免挤掉数字与帮助入口。

## 后续边界

后2尚未提供迁移申请任务、前2尚未提供网页文件加密，故不开放申请/导入/冻结入口。前1仅展示真实状态及准备说明，不宣称历史数据已经迁移，不提供临时明文接口。后端写事务仍是权限与冻结判断依据，前端状态不作为授权凭证。
