# 保险库用户流程补齐：前2

日期：2026-10-26。基于前1 520c903，接入后2 b8a8c76 的 F2 准备任务契约及原有 M1 迁移协议。

## 页面流程

迁移步骤内可申请准备、查看管理员及交付状态、取消尚未领取的申请。申请前明确冻结影响；申请本身不执行冻结、导出或源值清空。任务查询失败保留安全错误及重试入口，不猜测已准备完成。

管理员交付后，用户解锁保险库，选择安全交付的 JSONL 源文件，输入账号登录密码并确认文件来源，开始本地校验。账号密码只在本次运行内存中用于逐批重认证；不传给 Worker、不持久化，每个新 stage/receipt 请求获取 purpose=vault_migration 的一次性凭证。40101 不退出账号；停止、隐藏、超时、离页、登录失效均清理密码与文件引用并终止 Worker/请求。

默认仅短状态、真实数量和当前操作；数量详情按需展开，交付方式和完整步骤放入现有帮助。verified 停留“等待管理员最终切换”，不将它标为已迁移。最终切换、审核与备份闭环仍属于后3/前3。

## 本地边界与续跑

- M1 加密、快照一致性、摘要、读回比较及幂等逻辑抽到 src/lib/vault/migration-core.ts；tools/vault-migrate.ts 保持兼容导出。SHA256 不再依赖 Buffer。
- 使用现有已解锁 Worker 中的不可导出 CryptoKey。源文件通过 Blob/File 引用交给 Worker，主线程不读取内容；没有新增通用迁移解密回传接口。主线程只接收白名单网络请求、密文和数字进度。
- 浏览器上限8 MiB、2000条、单JSONL行64 KiB，流式逐行解析，不把文件读成多份完整字符串。核对 UTF-8、重复JSON键、完整集合、有序唯一ID、身份、保险库、源版本、软删除时间及元数据，拒绝空白/超限值。超出上限联系任务负责人使用现有本地迁移工具，见 token-vault-front3.md。
- stage/receipt 每批不超过100条，分别检查2 MiB/64 KiB正文上限；上传密文后必须GET实际暂存包，Worker解密与源值比较，再提交绑定包摘要的回执。保留原始空格和多字节。
- 结果不确定时重试同一request_id、版本及密文。Worker内仅保留尚待确认的密文请求；刷新后不依赖本地日志，重新解锁、选择源文件并从服务端读取实际进度，已暂存条目不重新加密，已验证条目不重复回执。
- 不持久化源文件、原值、密码或原始密钥，也不在业务HTTP中发送源值/源摘要。网络桥接严格限制路由与字段，不能被用于任意接口或明文上传。
- 429显示等待时间并遵守Retry-After；共享核心最多8次限流重试，不无限循环，也不逐批弹密码框。后台等待仍遵循5分钟无操作自动锁定。
- 多会话使用服务端版本控制；分页变化/冲突停止处理并提示刷新，不覆盖他人暂存结果。停止客户端不能回滚已提交服务端事务，后续以读回状态为准。
